AI Appointment Scheduler

Full-Stack Web + RAG Assistant

Students book faculty office hours from a live calendar, and an AI assistant answers from a knowledge base with citations and prepares bookings and changes that only run after the user confirms. The university theme is sample data; the flow fits any booking use case. Maintainable and strictly typed: Next.js 16, PostgreSQL with pgvector, Prisma, Auth.js, the Vercel AI SDK, Zod validation, a shared service layer, Docker, and CI.

  • 450+unit, integration, and e2e tests
  • 112live assistant checks passing
  • 93%of input tokens served from cache

Engineering highlights

  • The AI can't act alone. Suggested bookings and cancellations need your confirmation before they run.
  • Answers cite their sources. Replies come from a knowledge base and name the documents used.
  • Concurrency-safe bookings. Row locks and conditional updates stop simultaneous requests, proven by race tests.
  • Secure by default. Nonce-based CSP, per-user and per-IP rate limits, server-side role checks.

Student-Faculty Services v2

Full-Stack Web App · Capstone Rewrite

A full rewrite of my senior capstone. Students book 5 to 45 minute slots in faculty office hours; faculty set their hours, closures, and booking rules, and approve sessions. It includes undo, reminders, ratings, and a waitlist. React 19 and TypeScript front end, a layered, framework-free PHP 8.4 API on MariaDB, deployed by GitHub Actions only when every test passes.

  • 400+PHPUnit, Vitest, and Playwright tests
  • 46REST API endpoints, no framework
  • 100/100Lighthouse accessibility and best-practices scores

Engineering highlights

  • Undo that can't lose a slot. Cancellations can be undone for 10 seconds; the slot is held and undo re-checks every rule.
  • Reliable reminders. One a day before, in the app or by email, cancelled with the appointment and never sent twice.
  • Waitlist alerts, once. Join a waitlist when nothing is free and get one alert when a time opens, however it opened.
  • Ten booking rules, one transaction. Notice, overlaps, limits and closures are checked together, all or nothing.
